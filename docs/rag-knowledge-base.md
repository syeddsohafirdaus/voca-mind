# RAG Knowledge Base Architecture Specification: Voca Mind (`voca-mind`)

This document specifies the design, governance, chunking strategy, and privacy boundaries for the **Curated Retrieval-Augmented Generation (RAG) Knowledge Base** in **Voca Mind**.

---

## 1. Why Voca Mind Uses RAG

Large Language Models (LLMs) can generate fluent text but risk hallucinating medical or psychoeducational claims if ungrounded. Voca Mind uses a Retrieval-Augmented Generation (RAG) architecture to anchor AI dialogue in vetted, authoritative psychoeducational materials (such as grounding techniques, sleep hygiene principles, and stress management tools).

---

## 2. Responsibilities of the RAG Subsystem

### What RAG IS Responsible For:
- Providing authoritative, non-diagnostic psychoeducational context to ground conversational AI responses.
- Ensuring source provenance and metadata attribution for all retrieved information.
- Enabling consistent, reviewed educational information retrieval across dialogue turns.

### What RAG IS NOT Responsible For:
- **NOT** diagnosing mental-health conditions or recommending medical treatment.
- **NOT** prescribing or advising on medication regimens.
- **NOT** storing individual user statements, conversation history, or personal memories.
- **NOT** replacing human emergency crisis response or professional care.

---

## 3. Strict Boundary Separation: Curated Knowledge vs. User Memory

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│                       SYSTEM BOUNDARY SEPARATION                           │
├─────────────────────────────────────────────────────────────────────────────┤
│ 1. CURATED KNOWLEDGE BASE (knowledge_base/)                                 │
│    - Contains: Reviewed, external, impersonal psychoeducational documents.  │
│    - Storage: Qdrant Vector Collection (Knowledge Base).                    │
│    - Rule: Read-only for AI dialogue. Never contains user statements.       │
├─────────────────────────────────────────────────────────────────────────────┤
│ 2. PERSONAL USER MEMORY (PostgreSQL memories / summaries)                   │
│    - Contains: User-stated preferences, goals, and factual statements.       │
│    - Storage: PostgreSQL DB (user_id scoped).                               │
│    - Rule: Scoped exclusively to the individual user.                       │
└─────────────────────────────────────────────────────────────────────────────┘
```

> [!CAUTION]
> **Fundamental Architectural Rule:** 
> The knowledge base contains curated external information. User memory contains user-provided information. They are completely separate systems. User statements must **NEVER** be written into the curated knowledge base automatically.

---

## 4. Source Provenance & Review Requirements

- **Provenance:** Every document in `knowledge_base/` must cite its authoritative source name, publishing organization, and canonical URL.
- **Review Requirement:** Documents undergo formal review before ingestion. Unreviewed documents (`reviewed: false`) cannot be embedded into production vector collections.

---

## 5. Chunking Strategy & Metadata Preservation

### 5.1 Chunking Mechanics
- **Max Chunk Size:** 500 characters (configurable).
- **Overlap:** 50 characters (sliding window).
- **Deterministic Chunk IDs:** Formatted as `{document_id}_c{chunk_index:03d}` guaranteeing identical output for identical inputs.

### 5.2 Preserved Metadata Schema
Every chunk inherits structured metadata preserving full provenance:
- `document_id`
- `source_name` & `source_url`
- `publisher`
- `source_type` (`guideline`, `public_health_information`, `educational_resource`, `crisis_resource`, `research_summary`)
- `topic` & `language`
- `version` & `reviewed` status
- `start_char`, `end_char`, and `total_chunks`

---

## 6. Future Embedding & Qdrant Vector DB Pipeline

In future phases:
1. **Embedding Generation:** Chunks generated by `chunk_document()` will be passed to an embedding model (e.g. OpenAI `text-embedding-3-small`).
2. **Vector Indexing:** Dense vectors along with structured `ChunkMetadata` payloads will be indexed into Qdrant vector collections.
3. **Similarity Retrieval:** During user dialogue, search queries will retrieve top-k matching educational chunks filtered by `reviewed == true`.

---

## 7. Security & Privacy Requirements

- **No User PII:** The knowledge base contains zero personal user identifiers, conversation IDs, or sensitive user transcripts.
- **Offline / Isolated Ingestion:** Ingestion processing occurs via local server-side scripts; no raw content is exposed publicly without review.
